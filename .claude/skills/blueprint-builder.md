# blueprint-builder

Generate a Hadron blueprint from a natural language description. Creates the YAML blueprint file ready for registration with Hadron.

## Usage
`/blueprint-builder <name> — <description>`

**name**: Blueprint name in kebab-case (e.g., "run-integration-tests", "backup-postgres")
**description**: What the blueprint should do

## Examples
- `/blueprint-builder run-integration-tests — Run go test with race detection on all packages in a project, outputting a JUnit XML report`
- `/blueprint-builder sync-cortex-backup — Export all Cortex namespaces to a timestamped JSON file in ~/.cortex/backups/`

## Instructions

1. **Parse the name and description** from arguments.

2. **Determine the blueprint structure** based on the description:
   - Identify the primary action (build, test, deploy, backup, audit, etc.)
   - Identify required inputs (project path, config, flags)
   - Identify expected outputs (files, reports, exit codes)
   - Identify error conditions

3. **Check for similar existing blueprints**:
   - Use `hadron_blueprints_list` to see what already exists
   - If a similar blueprint exists, warn and suggest extending it instead

4. **Generate the blueprint YAML**:

```yaml
# Blueprint: <name>
# Generated by Mentat blueprint-builder
# Date: <ISO date>

name: <name>
description: <description>
version: "1.0"

inputs:
  - name: <input_name>
    type: string
    required: true
    description: <what this input is>
    default: <default value if applicable>

steps:
  - name: <step_name>
    command: <shell command>
    working_dir: "{{project_path}}"
    timeout: <seconds>
    on_failure: <abort|continue|retry>

  - name: <step_name>
    command: <shell command>
    depends_on: <previous step if needed>

outputs:
  - name: <output_name>
    type: <file|stdout|exit_code>
    path: <if file type>

metadata:
  category: <build|test|audit|backup|deploy|report|cleanup>
  projects: ["*"]  # or specific project IDs
  tags:
    - <relevant tag>
```

5. **Write the blueprint file**:
   - Path: `~/.hadron/blueprints/<name>.yaml`
   - If the directory doesn't exist, create it

6. **Validate the blueprint**:
   - Use `hadron_blueprint_validate` if available
   - Otherwise, check YAML syntax and required fields

7. **Register with Hadron**:
   - Hadron auto-discovers blueprints in `~/.hadron/blueprints/`
   - If Hadron is running, it will pick up the new blueprint on next scan
   - Use `hadron_blueprints_list` to confirm registration

8. **Output**:

```
=== BLUEPRINT CREATED ===
Name: <name>
Path: ~/.hadron/blueprints/<name>.yaml
Category: <category>
Inputs: <list of input names>
Steps: <N> steps
Status: <written|validated|registered>

To run: hadron_run_enqueue blueprint="<name>" inputs={...}
To test: Review the blueprint, then run with a test project

Tool broker: This blueprint will be surfaced for intent "<intent>"
  (via rule: bp-<category> in default-rules.yaml)
=== END ===
```

## When to Use
- When you need a new automation that doesn't exist yet
- When a repeatable multi-step process should be codified
- When the user describes a workflow that should be a blueprint
