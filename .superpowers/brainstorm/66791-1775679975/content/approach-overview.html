Four Features — Approach Overview

Scoping and sizing each feature. Click the one you'd like to discuss first, or we'll go top to bottom.

1

Workflow Progress Panel

New RightRail tab — mirrors Work tab structure. Shows internal pipeline runs with step-by-step progress, status badges, timing. Needs new REST API routes to expose internal/workflow state.

Scope

  • New REST endpoints: GET /api/workflows, GET /api/workflows/{id}, GET /api/workflows/{id}/events
  • New RightRail tab + icon registration
  • WorkflowTab component (list view + detail view)
  • WorkflowRunCard, WorkflowStepItem components
  • SSE or polling for live progress

Effort

  • Backend: Medium — API routes wrapping existing RunState/StepState
  • Frontend: Medium — new tab + 3-4 components, follows Work tab patterns
  • Risk: Low — well-defined data model already exists
2

Memory Viewer

Modal via /memory slash command — full CRUD on agent memories. Browse by scope (session/project/user), search, filter by tags/origin/confidence. Create, edit, delete, promote/deprecate.

Scope

  • New REST endpoints: GET/POST/PUT/DELETE /api/memories
  • Slash command registration for /memory
  • MemoryModal component with list + detail + edit form
  • Scope switcher, tag filter, search bar
  • Status lifecycle UI (draft → reviewed → canonical → deprecated)

Effort

  • Backend: Medium — REST wrapper around existing MemoryService
  • Frontend: Medium-High — modal with multiple views, form validation, status transitions
  • Risk: Low — memory service is stable, just exposing via REST
3

Tool Load Preferences

Added to existing ToolDashboard — per-tool toggle (auto/opt-in) with source layer badge showing where the effective preference comes from.

Scope

  • No new API routes — GET /api/tools/all and PUT /api/tools/load-preferences are ready
  • Extend ToolDashboard with load type column
  • Toggle switch per tool row
  • Source badge (user / project / agent / manifest / default)

Effort

  • Backend: None — APIs ready
  • Frontend: Low — extend existing component, add toggle + badge
  • Risk: Very low
4

Worker Status UI

RightRail widget + Settings panel — widget shows active worker count with expandable list. Settings panel has full detail with cancel buttons. Both use existing APIs.

Scope

  • No new API routes — GET /api/workers and POST /api/workers/{id}/cancel are ready
  • WorkerStatusWidget for RightRail (compact card)
  • WorkerStatusPanel for Settings > Observability (full table)
  • Polling interval for live updates

Effort

  • Backend: None — APIs ready
  • Frontend: Low — widget + settings panel, straightforward data display
  • Risk: Very low

Recommended Build Order

1. Tool Load Preferences (low effort, APIs ready) → 2. Worker Status UI (low effort, APIs ready) → 3. Workflow Progress Panel (needs API + frontend) → 4. Memory Viewer (most complex, needs API + modal + CRUD)
