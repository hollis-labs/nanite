## What shipped, concretely

- **Package move** (`internal/selftools`, task `01`) — self-tool definitions and dispatch moved out of `internal/mcp` in full. `internal/mcp` no longer contains `SelfToolsTransport` or any `self_tools_*.go` file (confirmed: `ls internal/mcp` shows only non-self-tool files — `dev_tools.go`, `general_tools.go`, `code_exec_tools.go`, `elicitation.go`, `manager.go`, `naming.go`, `tool_ctx.go`, `http_transport.go`, `validate.go`, `web_fetch_resilience.go`, `stdio_transport.go`, `plugin_transport.go`, `vanta_descriptions.go`, plus their tests). `internal/selftools` (55 files as of this writing — the task's own original estimate was 16 non-test files; the real count that had to move was 19 non-test + 28 test files, discovered mid-task via a more thorough content-based sweep, not just a struct/method grep) now holds all of it, plus the `examples/` golden-example directory (68 JSON files, moved for the `//go:embed` directive to keep working). A handful of `internal/mcp` helpers (`errorResult`, `textResult`, `intArg`, `elicitUserInput`, `elicitationCreateParams`, `elicitationRequestedSchema`) had to be exported — they're genuinely general MCP-transport infrastructure with no other legitimate home, not duplicated. The one new import edge this move introduces is `internal/selftools` → `internal/mcp` (for the wire-level `Tool`/`ToolResult` types, which stay in `internal/mcp`), confirmed one-directional and safe.
- **Reactive-layer schema** (`internal/store/migrations/126_selftool_reactions.sql`, task `02`) — two new tables: `selftool_reaction_kinds` (lookup, `slug TEXT PRIMARY KEY`, seeded with exactly 4 rows: `render_card`/`internal_api_call` both `implemented=1`, `external_api_call`/`callback` both `implemented=0`) and `selftool_reactions` (config, `id TEXT PRIMARY KEY`, `tool_name`, `reaction_kind_id` FK to the lookup table, `config` JSON, `enabled`, `created_at`, indexed on `(tool_name, enabled)`). Deliberately no combining-algorithm column — a self-tool's own reactions are meant to fire together, not compete, unlike reflexes. `internal/store/selftool_reactions.go` — `GetSelftoolReactionKind`, `ListEnabledSelftoolReactions`, `InsertSelftoolReaction`. Migration `126` landed first against the shared `125` baseline (see "Cross-batch note" below).
- **Reaction engine core** (`internal/selftools/reactions`, task `03`) — `Engine`/`NewEngine(store, httpClient, logger)`/`Fire(ctx, toolName, payload) (Result, error)`. Looks up a tool's enabled reactions and, per row: executes `internal_api_call` synchronously via a plain `*http.Client` call against a fully-qualified same-process URL (no auth/retry/idempotency — illustrative only, per the README's own scope fence); resolves `render_card` into an envelope-shaped JSON payload (`ResolveRenderCard`, matching the wire shape `{kind, version, type, data}` `callShowCard` already uses) without attempting delivery; defensively skips `external_api_call`/`callback` (seeded `implemented=false`) with a recorded, non-fatal `skipped_not_implemented` outcome even if a future operator hand-flips one to enabled before real executor code exists. The engine only ever imports `internal/store` plus stdlib — confirmed via `go list -deps ./internal/selftools/...` showing no `internal/chat`/`internal/service` entry, both at build time and independently by the reviewer. This is the load-bearing import-cycle constraint the whole design hinges on.
- **`render_card` marker construction** (`internal/selftools/render_card_marker.go`'s `EmbedRenderCardMarker(label, resolvedEnvelopeJSON string) string`, task `04`) — produces the exact marker format `callShowCard` already produces (`fmt.Sprintf("%s\n<!--ENVELOPE_DATA:%s:ENVELOPE_DATA-->", label, resolvedEnvelopeJSON)`, byte-identical, confirmed by direct source comparison), so a `render_card` reaction's marker is picked up correctly by all three existing marker consumers with zero changes to any of them.
- **Telemetry** (`internal/selftools/reactions/telemetry.go`'s `EmitReactionTrace(ctx, TraceStore, toolCallID string, result Result) error`, task `05`) — one `event_log` row per attempted reaction (including `skipped_not_implemented`), `category = "selftool_reaction"` (a new value, distinct from reflexes' `"reflex"`, independently queryable). A new, parallel, thin wrapper — deliberately not an extension of `internal/agent/reflexes/telemetry.go`. `session_id` is not threaded through (passed `""`) — `reactions.Fire` is session-agnostic by design; documented as a deliberate, non-blocking gap, not an oversight.
- **Envelope-marker-consumer collapse** (`internal/chat/envelope_marker.go`, task `06`) — the three previously-duplicated marker-extraction implementations (`internal/service/chat_generate.go`'s `captureEnvelopeData`, `internal/api/tools_call.go`'s `extractEnvelopeMarker`, `internal/mcpserver/handlers.go`'s `convertEnvelopeMarkers`) now all delegate their actual delimiter-scan to one shared, unexported scan function in `internal/chat`, exposed as two public functions — `ExtractEnvelopeMarker(text) (json, ok)` (single-marker read) and `ReplaceEnvelopeMarkers(text, replaceFn) string` (replace-all) — because the three callers turned out to have two genuinely different jobs (read-first-marker vs. replace-every-marker), not one. All three call-site function names/signatures were kept unchanged (each still does real, non-duplicated, call-site-specific work on top of the shared scan), so zero pre-existing tests needed updating. This task was independent of the render_card path working — the three consumers were already marker-agnostic before this cleanup.
- **Worked example — `task_update_report(id, msg)`** (`internal/selftools/self_tools_task_update_report.go`, task `07`) — the first real, live-wired caller of the reaction engine. A deliberately thin self-tool: validates `id`/`msg`, calls `Fire`, embeds the render_card marker if one resolved, calls `EmitReactionTrace`, returns a short confirmation — no persisted state of its own. Two reactions seeded at boot via a new Go-side idempotent seed function (`SeedTaskUpdateReportReactions`, mirroring `internal/agent/reflexes/seeds.go`'s pattern — chosen over a migration-time `INSERT` because the `internal_api_call` reaction's `endpoint` must be a fully-qualified `http://127.0.0.1:<port>/...` URL, which isn't known until the process's own `-port` flag is resolved in `main()`): one `render_card` targeting an `info-card` envelope, one `internal_api_call` targeting a new demo route, `POST /api/example/task-updates` (`internal/api/example_task_updates.go` — decodes, logs, returns 200, persists nothing). Wired live in `cmd/nanite/main.go`: `selfTools.Reactions = reactions.NewEngine(s, nil, slog.Default())` plus the seed call, right after `apiBaseURL` is resolved.

## Gotchas worth knowing before touching this code again

- **`created_at TEXT` vs. `time.Time` doesn't auto-scan in this codebase's SQLite driver.** `selftool_reactions.created_at` is declared `TEXT` (per the task's own DDL, not changed) — the driver only auto-converts a column into `time.Time` when it has `DATE`/`DATETIME`/`TIMESTAMP` affinity. `internal/store/selftool_reactions.go` does the conversion by hand (`RFC3339` format on write, `time.Parse` on read) — same fix shape as the pre-existing `durable_agents.go`'s `parseStoreTime` helper. If you add a new `time.Time`-typed field backed by a plain `TEXT` column elsewhere in this area, expect the same failure mode and the same fix.
- **`internal_api_call`'s `config.endpoint` must be a fully-qualified same-process URL, not a bare path.** The design doc's own worked-example illustration used a bare path (`/api/example/task-updates`); the real executor (`internal/selftools/reactions/internal_api_call.go`) treats `endpoint` as an opaque string handed straight to `http.NewRequestWithContext` — it never resolves a base URL itself. This is why task `07`'s seed had to move to a Go-side function run after `apiBaseURL` is known, not a migration-time `INSERT`. If you add a new `internal_api_call` reaction row by hand or via a future seed, get this wrong and the call will fail at request-construction time, not silently.
- **The new `/api/example/task-updates` route is exempted from `basicAuthMiddleware`, matching `/api/tools/call`'s existing exemption — and it's loopback-gated, not open.** The reaction engine's HTTP client sends no credentials, so this exemption is load-bearing for the seeded reaction to work in an authed deployment; the loopback check is what keeps the exemption safe. Don't remove the loopback check while "simplifying" this route later without re-adding an equivalent gate.
- **`ResolveRenderCard`'s envelope-wire-shape map literal (`{kind, version, type, data}`) is duplicated, not shared, against `buildShowEnvelope`'s identical literal** in `internal/selftools/self_tools_transport.go` — a structural consequence of the import-cycle constraint (`reactions` cannot import `selftools`), confirmed non-blocking by the Phase 1 reviewer but nothing enforces the two stay in sync if `buildShowEnvelope`'s base shape ever changes. Worth checking both if you ever touch the envelope wire shape itself.
- **`EmitReactionTrace`'s `session_id` and `tool_call_id` are not fully threaded through today.** `session_id` is hardcoded `""` (documented, deliberate — `Fire`/`Result` carry no session context by design). `tool_call_id` is passed `""` from `task_update_report`'s own handler too — no per-call `tool_use_id` is threaded into `ctx` at the self-tool-handler layer today; closing that gap would mean adding a new `ctx` key and touching the same three doors `06` just collapsed (`chat_tool_executor.go`, `tools_call.go`, `mcpserver/handlers.go`). Left as a documented, deferred gap by both `05` and `07` — not a regression, just incomplete correlation data if you go looking for it in `event_log`.
