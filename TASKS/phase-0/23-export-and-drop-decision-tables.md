**Export mechanism chosen**: a new `nanite admin export-decision-tables [--db path] [--dry-run] [--force]` subcommand (`cmd/nanite/admin_export_decisions.go`), following the existing `admin agent-broker-decisions` subcommand's precedent in `cmd/nanite/admin_cmd.go`. Key design point: it deliberately does **not** go through `store.New()` — `store.New` applies every pending goose migration unconditionally (`internal/store/store.go`'s `migrate()`), so once migration 111 (the drop) exists in the binary, a `store.New()` call would drop both tables before the export's own code ever ran. The command instead opens the SQLite file directly via the same `sqlitekit.OpenSingle` opener `store.New` uses (minus the `migrate()` step), reads both tables generically (column-name → value map, not hand-typed structs, so schema drift can't silently drop a field), and writes each row via `Store.LogEvent` with `event_type="strategy_decision_export"`/`category="strategy"` (detail = `approach`) and `event_type="broker_decision_export"`/`category="tool_broker"` (detail = `intent`), full original row JSON-encoded into `metadata`. Guards: refuses to re-run without `--force` if either export event_type already has rows in `event_log` (prevents accidental duplicate export); after writing, re-counts `event_log` rows per `event_type` and compares against rows read — any mismatch is a hard non-zero exit with an explicit "do not deploy the drop migration" message, satisfying step 5's "a failed export must not silently precede a successful drop."

**Migration**: `internal/store/migrations/111_drop_broker_and_strategy_decisions.sql` (goose format; 110 was the prior highest). `DROP TABLE IF EXISTS broker_decisions` then `strategy_decisions` in the Up; the Down recreates both tables' final pre-drop shape (structure only, no data — same precedent as `110_drop_prompt_templates.sql`), including all their historical indexes (`idx_broker_decisions_session`, `idx_broker_decisions_outcome` from migration 031; `idx_strategy_decisions_session`, `idx_strategy_decisions_approach` from migration 034).
