## Context

TASKS.md Phase 3: *"...promptrouter's phrase catalog into reflex predicates (fixing the two phantom-agent reflex entries, and doing the `promptrouter` naming cleanup as part of this migration)."* TASKS.md Phase 0 explicitly deferred this: *"Deliberately not included here: renaming `promptrouter`'s 'reflex' vocabulary... since `promptrouter` itself is being absorbed into reflexes in Phase 3, renaming its internals now and migrating them shortly after is likely wasted motion."*

### The catalog and the naming collision

`internal/promptrouter/catalog.go` (274 lines) carries a `Reflex` struct (`Triggers`/`Resolution`/`SideEffects` fields) and `BuiltinReflexes()` — a hardcoded Go-literal list of 8 entries. Its own package doc-comment (lines 1-27) records that this package was **previously named `internal/reflex`**, renamed specifically to stop it colliding with `internal/agent/reflexes` — per `GLOSSARY.md`, "reflexes" is now reserved exclusively for the agent-steering engine. Every identifier below still carries the old "reflex" vocabulary and needs renaming as part of this migration (not before — see Phase 0's deferral note above):

- `Reflex` struct (`catalog.go:91-107`) — fields `ID`, `Triggers`, `ResolvesTo`, `SideEffects`, `Priority`.
- `Triggers` struct (`:32-45`) — `UserPhraseAnyOf`, `ScopeTierHint`, `ExecutionPatternHint`.
- `Resolution` struct (`:48-73`) — `Pattern`, `Role`, `Profile`, `WorkflowName`.
- `SideEffects` struct (`:76-86`) — `ModeSignal`, `DispatchVia`.
- `BuiltinReflexes()` (`:118`) — the catalog itself, 8 entries.
- `ReflexMatch`, `Match()`, `MatchAll()` (`matcher.go:13-98`).
- `MatchLogger`, `LogReflexMatch`, `ReflexMatchEntry`, `AssignRoleWithReflex()`, `reflexMatchToAssignment()` (`dispatcher.go:10-137`).
- `MergeReflexes()` (`dispatcher.go:174-186`).
- `ReflexYAML`/`TriggersYAML`/`ResolutionYAML`/`SideEffectsYAML`, `LoadUserReflexes()`, `reflexFromYAML()` (`loader.go` — the `~/.nanite/reflexes/*.yaml` user-override schema).

### The two phantom entries — definitively identified

`documentor-mention` (`catalog.go:206-228`) and `strategist-mention` (`catalog.go:229-254`) both leave `Resolution.Profile` empty on purpose — inline comments confirm no matching agent profile exists (`documentor-mention`: no `documentor` profile at all; `strategist-mention`: `.nanite/agents/content-strategist.md` exists but is an unrelated, narrower Glyph-editorial role). Both fall back to `AssignRole`'s generic `worker` default rather than routing anywhere meaningful. The other 6 catalog entries (`worker`/`planner`/`researcher`/`reviewer`-resolving) all correctly resolve to real, existing profiles today — `researcher.md`/`reviewer.md` were added specifically to close this exact gap for those two slugs (see their own header comments). **"Fixing" the two phantom entries means one of: (a) build/assign a real profile each can resolve to, or (b) delete the phantom entries from the catalog if no real profile is wanted.** This task doesn't pre-decide which — the migration is the natural point to make that call, since a still-phantom entry has no sensible reflex-predicate translation (a `dispatch_to_agent` reflex needs a real target).

### A second, independent consumer must not be left stranded

`internal/mcp/self_tools_dispatch.go`'s `callExecuteTask` (~lines 116-154) runs its own separate match against `st.ReflexSet` (loaded via `promptrouter.LoadUserReflexes()`, potentially including user overrides beyond `BuiltinReflexes()`) to populate `dispatch.ReflexHints` for the `task_execute` self-tool's dispatch call. `chat_broker_dispatch.go`'s header comment explicitly treats this as a deliberately separate layer from the upstream broker path task 01 retires ("Both layers run. Don't collapse them."). Retiring `internal/promptrouter` outright removes this consumer's data source — this task must give it an equivalent (reading from the migrated reflex predicates instead of the old catalog), not just delete it and let `task_execute`'s dispatch hints silently go blank.

## What to do

1. For each of the 8 `BuiltinReflexes()` entries, design and create an equivalent DB-backed reflex row (using the `dispatch_to_agent` action kind from task 01, or whatever trigger/action shape task 01 settled on): phrase-list triggers (`UserPhraseAnyOf`) map onto the reflex engine's regex-match trigger support (a documented superset per architecture doc 03 — confirm the regex engine can express a simple "any of these phrases" match cleanly, escaping as needed) plus the existing `ScopeTierHint`/`ExecutionPatternHint` predicates.
2. Resolve the two phantom entries per the Context discussion — either assign a real target profile or drop the entry; document the choice made.
3. Decide what replaces the `~/.nanite/reflexes/*.yaml` user-override convention (`loader.go`) — the DB is now authoritative for reflexes generally (per the construction-model principle), so this is likely "operators use the same `agent_reflexes` CRUD path everyone else uses," not a parallel YAML-file override system. Confirm no real user currently relies on a populated override file before removing the loader (check `~/.nanite/reflexes/` for actual content, not just the code path).
4. Give `internal/mcp/self_tools_dispatch.go`'s `callExecuteTask` an equivalent data source for `dispatch.ReflexHints` against the migrated reflex predicates, preserving its deliberate independence from the upstream dispatch path (per the header-comment instruction not to collapse the two layers).
5. Delete `internal/promptrouter` in full once nothing references it. Confirm via grep that `chat_broker_dispatch.go` (emptied by task 01) has no lingering import.
6. Update or retire `docs/promptrouter-catalog.md`, `docs/promptrouter-authoring.md`, `docs/agent-pattern-catalog.md` — don't leave docs describing a deleted package.

### Six non-phantom entries: migrated as `dispatch_to_agent` reflex seeds

Added to `internal/agent/reflexes/seeds.go` (class=`advisor`, alongside task 02's `dispatch_to_agent_open_subagent`): `dispatch_to_agent_background_long_task`, `dispatch_to_agent_planner_mention`, `dispatch_to_agent_planner_large_task`, `dispatch_to_agent_researcher_mention`, `dispatch_to_agent_reviewer_mention`, `dispatch_to_agent_worker_execute`. Each carries forward the old catalog's `agent_slug` target (worker/planner/planner/researcher/reviewer/worker respectively) in `action_spec` (task 02's locked `{"agent_slug","confidence","reason"}` shape — not redesigned here).

- **Trigger shape**: `user_regex_window` (`window=1`) over the synthetic current-turn `UserMessages[0]` entry task 02 built (`chat_reflex_dispatch.go`'s design note 3) — a case-insensitive regex alternation built by a new `anyPhraseRegex` helper (`regexp.QuoteMeta`-escapes each phrase before joining, so future phrase edits are safe by construction even though none of the current phrases actually contain a regex metacharacter). Entries that originally carried a `ScopeTierHint`/`ExecutionPatternHint` guard `AND` that phrase window with a `scope_tier`/`execution_pattern` equality predicate (task 02's two new predicate kinds). `ScopeTierHint`'s old `>=` ("this tier or broader") semantics don't map onto `scope_tier`'s plain equality directly — reproduced with an `OR` over every tier at or above the hint (only needed for `planner-large-task`'s `large` hint → `OR(scope_tier=large, scope_tier=open)`; `planner-mention`'s `open` hint needs no `OR` since open is the top tier already).
- **Priority**: every migrated entry is `> 10` (above `dispatch_to_agent_open_subagent`'s priority), preserving the retired broker's Rule-1-beats-Rule-5 ordering (task 02's own design note: "a specific phrase match wins over the general tier/pattern rule"). Relative ordering among the six preserves the original catalog's `Priority` field ordering (60/50/45/35/30/20 vs. original 25/20/18/15/15/10), rescaled upward so DB `created_at` tie-break timing never has to matter. `confidence` in each `action_spec` is the *original* promptrouter `Priority`/100.0 (the same derivation task 02's retired broker used for `in.ReflexConfidence`) — audit/telemetry only, not gated on.
- **Deliberate behavior narrowing, documented for the record**: the migrated `action_spec` shape carries only `agent_slug`/`confidence`/`reason` — no `HintTier`/`HintPattern`/`Mode`/`WorkflowName`. Traced through `dispatch.ExecuteTask` (`internal/dispatch/execute.go`) before implementing: `AgentSlug` is the *only* field of the old `ReflexHints` that ever had an observable effect on what got spawned — `Mode`/`DispatchVia` were always coerced back to sync inside `ExecuteTask` ("ExecuteTask must capture, so async is coerced"), and `Role`/tier-pattern-derived hints only fed a cosmetic title-fallback string (`"%s result"`) used when the spawned agent's own envelope output was absent. This is not a regression from what promptrouter actually did *at this call site* — it's the same conclusion task 02's Work Log already reached about the old broker ("declared intent + event_log telemetry, not an enforced override").

### `~/.nanite/reflexes/*.yaml` — checked for real content, found real content, retired the loader anyway (with a documented, low-risk reason)

Per the task's explicit instruction, checked the actual directory contents on disk before removing `promptrouter.LoadUserReflexes`/the loader code path — **found six real, substantively-authored files** (`conductor-approval.yaml`, `conductor-dispatch-project.yaml`, `conductor-note-capture.yaml`, `conductor-note-fragments.yaml`, `conductor-note-nil.yaml`, `conductor-research-drop.yaml`, dated 2026-08-16, referenced by `docs/conductor-usage.md` and `docs/architecture/conductor-console-design.md`), not stale leftovers. Traced their actual wiring before deciding what to do:

- The **only** production consumer of `LoadUserReflexes`'s output was `main.go`'s `selfTools.ReflexSet = promptrouter.MergeReflexes(BuiltinReflexes(), userReflexes)` — i.e. `callExecuteTask`'s own downstream matcher, which only ever runs *after* `task_execute` is already being invoked. The retired agent-broker's Rule 1 (`chat_broker_dispatch.go`'s `buildBrokerInput`) — the call site these files' own header comments say they were designed to influence ("keeps Conductor from being force-dispatched") — used `promptrouter.BuiltinReflexes()` directly, **never** the merged user-override set. So these files never actually fed the mechanism their own comments claim.
- All six leave `resolves_to.profile` empty by design (their whole point is "stay in chat, don't dispatch"). At the call site they actually *did* reach (`callExecuteTask`), an empty `Profile` means `ReflexHints.AgentSlug` is empty, which is a no-op override — `AssignRole`'s own default stands. None of the six set a `scope_tier_hint`/`execution_pattern_hint` either, so the hint-override path was also inert for them. The only real effect a match had was a `playbook_match_log` audit-log row (and a since-cut session-mode-bus signal — Modes were cut in full by `TASKS/phase-0/21-cut-modes.md`, independent of this task).
- `docs/conductor-usage.md` itself already documents (and this task's edit to that doc doesn't change) that Conductor's actual behavior for these phrasings is driven by its system prompt, not this middleware layer.

**Conclusion, not an escalation**: retiring the loader drops an already-audit-log-only mechanism, not a behavior guarantee — Conductor's observable behavior for these six phrasings is unaffected. The **files themselves were left untouched on disk** (`~/.nanite/reflexes/*.yaml`, outside the repo, still there, mtimes unchanged — verified via `ls -la` before and after) — this migration does not delete any operator-owned file. `docs/conductor-usage.md` and `docs/architecture/conductor-console-design.md` were both corrected (see Docs section below) to state plainly what these files' actual wired effect always was (not what their own header comments claimed), rather than silently going quiet about a mechanism that stopped running. If deterministic audit tagging for these specific phrasings is wanted again, it needs a new reflex action-kind concept ("match but don't dispatch") that doesn't exist yet — flagged as a real gap, not built here (the current `dispatch_to_agent` action kind is a positive "route to X" primitive, not a place to bolt on a fifth, unrelated semantic).

### Second consumer (`callExecuteTask`) given an equivalent, deliberately independent data source

`internal/mcp/self_tools_dispatch.go` gets a new `matchDispatchToAgentReflex` method: reads live `dispatch_to_agent` `agent_reflexes` rows directly off `st.Store` (via `Store.ListAgentReflexesForAgent`, resolving the caller's agent class from `CallerProfileFromContext(ctx)` → `Store.GetAgent(...).Class`, defaulting to `advisor` the same way `attemptReflexDispatch` does), evaluates each with `reflexes.EvaluateTrigger` (first fire in priority-DESC order wins), and returns a `dispatch.ReflexHints{AgentSlug, ReflexID}` or `nil`. This is **not** a call into `internal/service`'s `attemptReflexDispatch` — `internal/mcp` cannot import `internal/service` (cycle: service already imports mcp), and the retired `chat_broker_dispatch.go`'s own header comment explicitly said "both layers run, don't collapse them" for the pre-migration broker/promptrouter pair; that instruction still applies conceptually to this pair post-migration. Both call sites now independently read and evaluate the *same* `agent_reflexes` table — deliberately duplicated evaluation logic, not a shared decision object — preserving the original two-layer architecture task 01/02 established, just with both layers now pointed at the DB instead of one at a Go-literal catalog and one at agentkit's broker.

**A capability this narrows, documented rather than silently dropped**: the old `callExecuteTask` matcher also supported `ReflexHints.WorkflowName` — a caller-constructed `promptrouter.Reflex{ResolvesTo: {WorkflowName: "..."}}` could route a matched phrase straight to a named workflow, bypassing `AssignRole` entirely (`CW-20260814-0002`). The `dispatch_to_agent` action_spec shape (task 02's locked design) has no `workflow_name` field, so this specific *implicit-phrase-triggers-a-workflow* path is retired along with promptrouter — verified this doesn't strand a unique capability: `workflow_run` (`internal/mcp/self_tools_workflow_run.go`) is a live, direct, already-documented self-tool for invoking a named workflow, and was always the more legible mechanism for that job. Deleted the two tests exercising the retired path (`self_tools_dispatch_workflow_test.go`'s `TestCallExecuteTask_ReflexWorkflowName_RoutesToWorkflowLauncher` / `TestCallExecuteTask_NonWorkflowReflex_LeavesWorkflowNameEmpty`); preserved the shared test doubles that file also defined (`recordingSpawner`, still needed by the rewritten audit test; `stubWorkflowLauncher`, still needed by `self_tools_workflow_run_test.go`'s own, unrelated direct-invocation tests) by moving them into a new `self_tools_dispatch_test_helpers_test.go`. `dispatch.ExecuteTask`'s own `RoleWorkflow`/`WorkflowLauncher` machinery is untouched and still independently tested (`internal/dispatch/execute_test.go`) — only the reflex-triggered auto-population of `ReflexHints.WorkflowName` at this one call site is gone.
