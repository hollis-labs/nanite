## Work log

**Step 1 — the real emitter, actually traced (not assumed).** Grepped every literal occurrence of `plan-review` in the repo. `internal/subagent/service.go`'s comments (now ~1311/1529, drifted from the ~1309/1527 the task file cited) are confirmed **not** the emitter — `liftResultEnvelopes`/`extractLiftableEnvelopes` there are fully type-agnostic: they lift *any* structured envelope a subagent child produced onto the parent session, and `"plan-review"` appears only as an illustrative example in a doc comment. The real construction site is **`internal/selftools/self_tools.go:395-396`**, inside the `plan_create` tool's `Description` string — a natural-language instruction telling the LLM to write the literal `{"kind":"envelope","version":1,"type":"plan-review",...}` fenced `nanite-envelope` block itself, in its own response text, with placeholder values it fills in. Confirmed via `internal/selftools/self_tools_transport.go`'s `callPlanCreate` (the actual Go handler for the `plan_create` tool call): it only writes the `store.Plan` row and returns a text summary — it never constructs or appends any envelope JSON. (Contrast with `callTodoList`, which *does* build an envelope in Go.) So there is no Go call site to "update the real emitter" in the mechanical sense the task's Context expected — the emitter *is* the prompt string, and that's what had to change. `internal/chat/envelope.go`'s `ParseEnvelopes`/`ValidateEnvelope` (regex-extracts ` ```nanite-envelope ` blocks from assistant text, then checks `env.Type` against the manifest-loaded `registeredTypes` set) confirms this instruction is load-bearing, not cosmetic: once `plan-review` is removed from the manifest, an agent that still emitted the old block would get `unregistered_type` at parse time.
