## What shipped, concretely

- **Taxonomy schema** (`internal/store/migrations/124_reflex_action_taxonomy.sql`, 226 lines) — three new lookup tables (`reflex_action_categories`: 2 rows, `system_message`/`execute_action`; `reflex_action_kinds`: 6 rows, one per existing `action_kind` string, each carrying `category`/`combining_algorithm`/`default_recurrence_seconds`; `reflex_provenance_tiers`: 3 rows, `system`/`operator`/`plugin`) plus two new columns on `agent_reflexes` (`provenance_tier`, `recurrence_override_seconds`) — replaces the overloaded `priority` column's two undeclared meanings and the free-text `created_by` provenance string with real FK-backed structure. `action_kind` itself stays a plain TEXT column (not converted to an integer FK) — dozens of Go call sites string-compare it directly against `store.ReflexAction*` constants — but now carries a `REFERENCES reflex_action_kinds(name)` clause for real SQLite-enforced referential integrity, added essentially free during the same table-rebuild.
- **Recurrence cascade** (`internal/agent/reflexes/recurrence.go`, `EffectiveCooldown()` at line 36) — system default (15 min, a Go constant, `DefaultReflexCooldown`) → per-kind override (`reflex_action_kinds.default_recurrence_seconds`) → per-reflex override (`agent_reflexes.recurrence_override_seconds`) cascade, with an explicit `0` meaning "no cooldown" distinguished from `nil` meaning "unset." Wired into `EvaluateState`'s debounce (previously a hardcoded `15*time.Minute` literal) and, for the first time, actually enforced at the two `dispatch_to_agent` call sites (`attemptReflexDispatch`, `matchDispatchToAgentReflex`) — both previously had zero cooldown concept.
- **Shared `Resolve()` decision engine** (`internal/agent/reflexes/resolve.go`, `Resolve()` at line 177) — **the core deliverable.** One function, in the one package all three call sites already import without a cycle, that all three (`Engine.EvaluateState`, `attemptReflexDispatch`, `matchDispatchToAgentReflex`) now call for "which fired candidates actually get applied," instead of each hand-rolling its own priority-ordering/first-wins/all-fire loop. Implements the three combining algorithms from the design doc's Facet 2 (`deny_overrides`, `first_applicable`, `all_applicable`) per action kind, looked up via `01`'s lookup tables.
- **Turn-level halt fix** (`internal/service/chat_generate.go`) — `generateResponse` now inspects the actions returned by `evaluateAndInjectReflexes` for `store.ReflexActionHaltSession` and aborts (sends an error event, returns) **before** the LLM provider call later in the same function. Previously a fired `halt_session` reflex only stamped `halted_at` on the session row (`container.go`'s `HaltHook` → `MarkSessionHalted`, unchanged), checked on a *subsequent* request by `frontend_readiness.go` — the turn that triggered the halt reached the LLM anyway.
- **Provenance-tier enforcement gate** (`internal/store/migrations/125_reflex_action_kind_provenance_allow.sql`, 66 lines; `internal/api/reflexes.go`'s `validateReflexDefinition`) — a new join table `reflex_action_kind_provenance_allow` (16 of 18 possible `(kind, tier)` combinations allowed by default; `(halt_session, plugin)` and `(dispatch_to_agent, plugin)` denied by omission) enforced at write time on every real `InsertAgentReflex`/`UpdateAgentReflex`-adjacent CRUD path (`handleCreateAgentReflex`, `handlePatchAgentReflex`, `handleValidateReflex`). Explicitly documented as an adjustable default, not locked security policy — loosening/tightening it is a data change (`INSERT`/`DELETE` on the table), not a code change.
- **Unified reflex telemetry** (`internal/agent/reflexes/telemetry.go`, `EmitFirings()` at line 173) — one thin wrapper every `Resolve()` caller now goes through immediately after: one `event_log` write, one `Store.BumpAgentReflexFired` call, one `EmitReflexFired`/`EmitReflexActionStaged` plugin-hook pair, per real firing, regardless of which of the three call sites produced it. Previously `dispatch_to_agent` firings from the `task_execute` self-tool path (`matchDispatchToAgentReflex`) wrote to a completely separate table (`playbook_match_log`), never bumped `fired_count`, and never fired plugin hooks — the operator UI's reflex list could show `fired_count: 0` for a reflex actively routing turns through that path. `internal/store/reflex_log.go` (the `playbook_match_log` writer: `LogReflexMatch`/`ReflexMatchLogEntry`/`ListReflexMatchLog`) is deleted in full — confirmed via repo-wide grep no real reader existed (no API handler, no UI reference, no CLI report).

## The two concrete bugs this batch fixes, and how each was verified

1. **`force_tool_choice` co-firing** — two `force_tool_choice` reflexes naming different tools could both fire in the same pass and both land in the same `<system-reminder>` block, giving the LLM two competing imperatives. Fixed by classifying `force_tool_choice` as `first_applicable` (seeded in migration 124) — `Resolve()` structurally admits only one winner per kind under that algorithm. Verified through the real code path, not a mock: `TestFormatReflexReminder_ForceToolChoiceBug_ExactlyOneActionWins` and its tie-break sibling run end-to-end through the real `Engine.EvaluateState` → `formatReflexReminder`, asserting exactly one line survives naming the higher-priority tool (task `03`'s Work Log).
2. **`halt_session` not actually halting** — fixed in two parts, per the design doc's own two-part framing:
   - Same-pass preemption (task `03`): `Resolve()`'s `deny_overrides` algorithm — if a `halt_session` reflex fires, it wins outright and short-circuits the whole pass, no other action of any kind applies. Verified by `TestEvaluateState_HaltSessionPreemptsInjectReminder_SamePass`, real `Engine.EvaluateState` against a real store with a real seeded `reflex_action_kinds` row, a `halt_session` reflex at priority 10 and an `inject_reminder` reflex at priority 999 both firing in the same pass — asserts only the halt action survives, the reminder's `fired_count` stays 0.
   - Turn-level abort (task `04`): `TestGenerateResponse_HaltSessionReflex_AbortsTurnBeforeLLMCall` calls the real `generateResponse` (not a narrower helper) with a real DB-backed reflex row and a real `reflexes.Engine`, asserting both halves in one test — zero LLM provider calls (`mockProv.callCount == 0`) **and** the session row shows `halted_at`/`halted_reason` set. This test was mutation-tested (the fix was temporarily neutralized and confirmed the test fails with the expected messages, then reverted), not just written and trusted.
   - **One documented deviation from `04`'s own "Done means"**: its Done-means asked for a live dogfeed against a real deployed instance (temporarily lowering a threshold on one of the three real `halt_session` seeds and confirming no LLM call is billed). That dispatch's available toolset had no `cerberus_resource_*` MCP tools, so it used the task file's own documented automated-fallback clause instead (mutation-tested test proving both halves) rather than mutating a live production session. Not re-litigated here per this handoff's own scope — flagging so a future reader doesn't assume a live halt was ever actually fired against production during this batch; it wasn't. Migration `124` itself *was* verified live against production (below).

## The one open, deliberately-not-fixed gap

`store.ApprovePendingReflex` (`internal/store/agent_reflexes.go:658-671`) does its own raw `INSERT INTO agent_reflexes`, bypassing both `InsertAgentReflex` and `05`'s new `ActionKindAllowsProvenanceTier` gate entirely. It correctly hardcodes `provenance_tier='operator'` on the resulting row (mirroring the pre-existing `created_by` → `"operator:"+reviewedBy` collapse), but that value is never actually checked against `reflex_action_kind_provenance_allow`. **Harmless today** — every one of the 6 action kinds has an `('...', 'operator')` allow-list row, so this path always lands on an already-allowed pair by construction, not because anything checked it. **Latent risk**: if a future operator ever tightens the allow-list to restrict `operator` tier from declaring a specific kind, `ApprovePendingReflex` would silently not honor that restriction — it's the only write path into `agent_reflexes` that doesn't route through the Facet-3 gate.

This is not a defect in task `05` — `05`'s own task file explicitly scoped `ApprovePendingReflex`'s job as "preserve the collapse... not invent new approval-time behavior," and the fresh reviewer treated it as a non-blocking observation, not a finding requiring fix-before-close. Logged in full at `TASKS/ESCALATIONS.md`'s final entry (2026-08-20, "Reflex Action Taxonomy Phase 2 review: `ApprovePendingReflex` bypasses the Facet-3 provenance gate — HEADS-UP, not blocking, not fixed here") and already captured to Vanta memory at `user/chrispian/memory/followups/reflex_taxonomy_approve_pending_reflex_provenance_gate_bypass`. ## Gotchas worth knowing before touching this code again

- **`deny_overrides` is a cross-kind union, not per-kind.** `Resolve()` resolves `deny_overrides` as a union across *every* kind classified `deny_overrides` present in a pass, not scoped to one kind at a time. Only `halt_session` is seeded `deny_overrides` today, so this is unobservable in practice — but it's deliberate, documented in task `03`'s Work Log, and generalizes correctly if a second `deny_overrides` kind is ever added without needing to revisit `resolve.go`.
- **"Apply-failure no longer cascades" — a real, documented behavior narrowing.** Before this batch, the two `dispatch_to_agent` inline loops would fall through to the next-lower-priority candidate if the current best candidate's `Executor.Apply`/JSON-parse failed. `Resolve()`'s `first_applicable` picks exactly one candidate; if that one's `Apply` fails, no candidate of that kind is selected this pass — full stop, no cascade. Low-risk in practice: `Executor.Apply` can only fail here on malformed `action_spec` JSON, which `validateReflexDefinition` (`internal/api/reflexes.go:297-314`) already rejects at write time for anything created through the CRUD path — effectively unreachable for valid data, but worth knowing if you're debugging a "reflex silently didn't fire" report someday.
- **`event_log` is the telemetry sink — not a new dedicated table.** The design doc left this as an open implementation call (`event_log` vs. widening `playbook_match_log` vs. a new table). Task `06` chose `event_log` because it was already the majority path and general-purpose — document this if you're ever tempted to add a "reflex trace" table, since the intent was explicitly to consolidate onto the existing general-purpose sink, not fragment further.
- **`playbook_match_log`'s table and both its migrations (`032`, `094`) are intentionally still in place**, even though its entire Go write path (`ReflexMatchLogger`/`LogReflexMatch`/`internal/store/reflex_log.go`) is fully deleted. Matches this project's own standing precedent (`TASKS/adhoc/02`'s identical call on `tool_permissions`) — dropping a table via a new migration is a bigger, less-reversible move than this task asked for, and no clean need surfaced. If you're grepping for why a seemingly-dead table still exists, this is why; don't be surprised, and don't feel obligated to clean it up without a real reason.
- **The reviewer flagged one non-blocking style/behavior observation worth remembering, not a bug**: `resolveProvider`-adjacent code isn't part of this batch, but a similarly-shaped "fail-open with logging, not silent" pattern from `08` is now the house style for this package — if you add a fourth `Resolve()` caller or a new combining algorithm later, match `08`'s `slog.Warn` treatment for any new fail-open path rather than reintroducing a silent one.
