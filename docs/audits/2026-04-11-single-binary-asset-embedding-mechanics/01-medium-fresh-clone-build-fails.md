# [Medium] Fresh `git clone` + `go build` produces a broken SPA embed

**Scope:** single-binary asset embedding mechanics
**Topic:** Fresh checkout behavior
**Date:** 2026-04-11

## Problem

A fresh `git clone` followed by `go build ./cmd/nanite` compiles successfully but produces a binary whose embedded SPA serves a broken `index.html` that references JS and CSS bundles that were never embedded.

## Evidence

The embed directive at `internal/server/spa.go:10` uses the `all:` prefix:

```go
// internal/server/spa.go:10
//go:embed all:ui_dist
var embeddedUI embed.FS
```

The `.gitignore` excludes the Vite build output:

```
# .gitignore:44-45
# Embedded UI build assets (regenerated by npm run build)
internal/server/ui_dist/assets/
```

Only two files are tracked in git:

```
internal/server/ui_dist/index.html
internal/server/ui_dist/vite.svg
```

The committed `index.html` (`internal/server/ui_dist/index.html:8-9`) references hashed bundle filenames:

```html
<script type="module" crossorigin src="/assets/index-Civ-XPy0.js"></script>
<link rel="stylesheet" crossorigin href="/assets/index-DbYdIOur.css">
```

After a fresh clone, `go build` embeds only `index.html` and `vite.svg`. The `assets/` directory with JS/CSS bundles does not exist. The binary compiles without error because `//go:embed all:ui_dist` is satisfied by the two tracked files. At runtime, the SPA serves an HTML page that tries to load non-existent JS/CSS, resulting in a blank page.

The `Makefile` (`Makefile:4-6`) runs `build-ui` before `go build`, which populates the `assets/` directory. But `go build ./cmd/nanite` alone (which is documented in `backend.md` at the "Build & Run" section) does not.

## Impact

Any developer who clones the repo and runs `go build ./cmd/nanite` (rather than `make build`) gets a binary that compiles but serves a non-functional web UI. The `--dev` flag path works (serves placeholder HTML), but the default non-dev path is broken.

This is not a security or data-loss issue, but it is a silent build correctness problem. The Go compiler does not warn when `//go:embed` embeds fewer files than the application expects.

## Recommendation

Two options:

1. **Commit a placeholder `index.html`** that does not reference `assets/` bundles. The real `index.html` gets overwritten by `npm run build`. This ensures a fresh-clone `go build` produces a binary that at least shows a "run `make build` for the full UI" message instead of a blank page.

2. **Add a build-time check** (e.g., a `//go:generate` step or a pre-build script) that verifies `internal/server/ui_dist/assets/` exists before `go build`. This fails loudly instead of producing a broken binary.

Option 1 is simpler. The committed `index.html` is already stale (it references specific content-hashed filenames), so replacing it with a dev placeholder and letting the build overwrite it would be a net improvement.
