Notable non-blocking tooling quirk (recorded for the next worker who hits it,
not a finding about the codebase): `golangci-lint run -c <config> --output.json.path <relative-path>`
resolves the relative output path against the **directory containing the `-c`
config file** (here, `docs/audits/2026-08-21-go-quality/`), not the shell's
invocation cwd — this also explains why every issue's file path in
`golangci-baseline.log` is prefixed `../../../` (three levels back up to the
repo root from the config file's directory). A first attempt using a
shell-cwd-relative path (`docs/audits/2026-08-21-go-quality/raw-1d3bfd96/golangci-baseline.json`)
silently wrote to a nested, duplicated path instead
(`docs/audits/2026-08-21-go-quality/docs/audits/2026-08-21-go-quality/raw-1d3bfd96/...`)
— caught via `git status` showing an unexpected untracked `docs/audits/2026-08-21-go-quality/docs/`
directory, which was deleted before committing. Using an absolute path for
`--output.json.path` avoided the issue; `golangci-baseline.json` in this
directory was produced that way.
