# Patterns

Stub. Recurring, deliberate design patterns established across this review, worth reusing rather than reinventing per subsystem:

- **Composition over flat definition.** An Agent is Role + Scope + grants, not a monolithic record. Cards are meant to be composed from a small primitive set rather than growing a new top-level type per feature. Apply this by default when a new "kind of thing" is tempting to add — ask whether it's actually a composition of existing primitives first.
- **Cascading override, closest wins.** Role → agent → task (`.htaccess`/Kubernetes-RBAC-shaped): broad defaults, overridable at each more-specific layer. The right shape whenever "global default, sometimes needs a local override" comes up — don't build a bespoke resolution chain per feature (this codebase had at least three independent ones — provider selection, message-wake policy, session-intent classification — before they were collapsed into one).
- **Filters/hooks as the extension seam for anything a plugin might want to intercept.** Already reaches deep into the turn loop and reflexes (see `../architecture/09-plugin-system.md`). Prefer adding a new `Filter*`/`Emit*` hook over a bespoke plugin-specific mechanism when extending something plugins should be able to touch.
- **A live, queryable postmortem trail for anything that can fail silently.** `event_log`'s `event_type`/`category` + flexible `metadata` shape is the reusable answer — one polymorphic table with a discriminator, not a new dedicated table per subsystem that wants to log "what happened and why."
- **Hard, generous backstops instead of tunable strategic budgets.** `HardCeiling`-style non-resetting ceilings (a large, non-strategic number that's never meant to be hit in normal operation) catch genuine runaways without pretending to make a strategic decision. Prefer this over a "smart" budget that's supposed to be tuned — this codebase has repeated, direct evidence that the tunable-budget version produces worse outcomes (dead-end conversations, premature termination) than a generous backstop plus real activity-awareness.
- **Critical, universally-needed content is a structural default, not a per-agent-assignable optional template.** This codebase has hit the same failure mode twice: the tool-discovery escape hatch (`request_tools`/`tool_list`/`tool_describe`) and the post-compaction disclosure message were both built as things an agent had to be individually assigned, and in practice almost nothing ever got assigned — one real assignment across the whole system, in the compaction case. If every agent needs it, bake it into the mechanism unconditionally; don't make its presence depend on someone remembering to opt an agent in.
