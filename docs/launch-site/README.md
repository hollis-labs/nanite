# Nanite Launch Site Content

Draft markdown content for the initial public Nanite website.

These files are content-only and intentionally avoid framework-specific layout assumptions. The recommended initial navigation order is:

1. [Home](home.md)
2. [Why Nanite](why-nanite.md)
3. [Features](features.md)
4. [Use Cases](use-cases.md)
5. [How Nanite Works](how-it-works.md)
6. [Getting Started](getting-started.md)
7. [Plugins](plugins.md)
8. [Roadmap](roadmap.md)

Content stance:

- Audience: builders and developers.
- Voice: direct, technical, candid, indie-builder rather than marketing.
- Positioning: Nanite is an open agent platform and control pane, not just an agent harness.
- Runtime framing: balanced CLI and API story, with CLI-backed agents treated as first-class managed runtimes through planting, host policy, sandboxing, sessions, recovery, and steering.
- Roadmap framing: candid about rough edges and active hardening.
- Internal examples: Nanite building Nanite is the flagship story. Loom, Torque, Tether, and Tesseract can be mentioned in context, but there is no dedicated Hollis Labs stack page for launch.
- Status framing: active development, not officially released yet; no stage label required.
- Future-plans framing: open source first; do not rule out multi-user or larger product directions, but do not speculate.
